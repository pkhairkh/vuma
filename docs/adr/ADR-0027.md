# ADR-0027: Metal + MPS Host Layer for GPU Compute (macOS)

- **Status**: Accepted
- **Date**: 2026-08-04
- **Decision Maker**: VUMA project lead
- **Supersedes**: (none)
- **Superseded by**: (none)

## Context

ADR-0022 established that VUMA's GPU path uses pre-compiled SPIR-V
embedded as const byte arrays (V-26 Phase 2). On macOS, the SPIR-V is
cross-compiled to Metal Shading Language (MSL) via `spirv-cross --msl`,
then compiled to a .metallib by `xcrun -sdk macosx metal/metallib`.

This ADR documents the Metal host layer implementation: the Objective-C
shim that wraps the Metal framework and exposes the `mtl_*` functions
declared in `womb/ui/render/gpu_dispatch.vuma`. It also documents the
Metal Performance Shaders (MPS) wrapper for pre-built GPU kernels.

## Decision

**The Metal host layer is a thin Objective-C shim (`gpu_metal.m`) that
wraps the Metal framework and provides a compute-pipeline dispatch API.
The MPS wrapper (`gpu_mps.m`) provides pre-built GPU kernels for matrix
multiply, image processing, and ray tracing.**

### Architecture

```
VUMA program (womb/ui/render/gpu_dispatch.vuma)
  ↓ calls mtl_* / mps_* extern "C" functions
gpu_metal.m / gpu_mps.m (Objective-C shims, wrap Metal + MPS frameworks)
  ↓ calls Metal / MPS API
Metal framework (OS-provided, native on macOS)
  ↓ dispatches to GPU
GPU execution (Apple Silicon GPU or AMD GPU)
```

### Key design decisions

1. **Native Metal, no MoltenVK**: Per ADR-0022 §cross-platform-GPU,
   macOS uses native Metal (no MoltenVK translation overhead). MoltenVK
   is available as a fallback (via ADR-0026's gpu_vulkan.c) but native
   Metal is preferred.

2. **SPIR-V → MSL cross-compilation**: At build time, `spirv-cross --msl`
   converts the .spv files to .metal files. Then `xcrun -sdk macosx metal`
   compiles .metal → .ir, and `xcrun -sdk macosx metallib` links .ir →
   .metallib. The .metallib bytes are embedded in the VUMA binary via
   V-26 Phase 2 (.rodata).

3. **Single-device, single-queue**: One MTLDevice, one MTLCommandQueue.

4. **Synchronous dispatch**: `mtl_queue_submit_and_wait` calls
   `[cmd commit]` + `[cmd waitUntilCompleted]`.

5. **Threadgroup size 16×16×1**: Matches the GLSL `local_size_x/y = 16`
   in the compute shaders.

### MPS (Metal Performance Shaders)

MPS provides pre-built, highly-optimized GPU kernels for common operations:

- **MPSMatrixMultiplication**: Matrix C = alpha*A*B + beta*C. Uses
  tensor cores on Apple Silicon. Useful for transform hierarchy matrix
  multiply in 3D rendering.
- **MPSImageGaussianBlur**: Gaussian blur on RGBA8 textures. Useful for
  post-processing effects (bloom, depth-of-field).
- **MPSRayIntersector**: Ray-triangle intersection. Uses dedicated
  ray-tracing hardware on Apple Silicon (M1+). Foundation for GPU-
  accelerated ray tracing in VUMA's 3D renderer.
- **MPSMatrixDecompositionLU**: LU decomposition for solving linear
  systems. Useful for IK chains, physics constraints, and transform
  matrix inversion.

### Verified

- SPIR-V → MSL cross-compilation verified via `spirv-cross --msl`
  (tested in W1 of the GPU orchestration).
- The .metal output compiles syntactically (verified by inspection —
  full compilation requires macOS/xcrun).
- Runtime test requires macOS (Metal framework not available on Linux).

### Graphics Pipeline (v0.2.0-alpha.14)

The Metal shim now supports both compute AND graphics pipelines:

**Graphics pipeline functions:**
- `mtl_create_render_pipeline` — vertex + fragment functions from
  metallib, vertex descriptor (vec3 pos + vec2 tex_coord, stride 32),
  color format RGBA8Unorm, depth format Depth32Float.
- `mtl_cmd_begin_render_pass` — MTLRenderCommandEncoder with color +
  depth attachments (clear color to black, depth to 1.0).
- `mtl_cmd_bind_render_pipeline` — bind MTLRenderPipelineState.
- `mtl_cmd_bind_vertex_buffer_gfx` — bind vertex data to render encoder.
- `mtl_cmd_bind_gfx_uniform_buffer` — bind uniform to vertex + fragment.
- `mtl_cmd_draw_indexed` — drawIndexedPrimitives with u32 index buffer.
- `mtl_cmd_end_render_pass` — endEncoding.

**Texture support:**
- `mtl_create_texture` — RGBA8 texture from host data via
  replaceRegion:mipmapLevel:withBytes:bytesPerRow:.
- `mtl_cmd_bind_texture_gfx` — setFragmentTexture:atIndex:.

Note: The depth-stencil state (depth test enabled, LESS compare) is
set implicitly by the render pass having a depth attachment. A full
implementation would create an explicit MTLDepthStencilState.

## Consequences

### Positive
- VUMA programs can dispatch GPU compute work via native Metal on macOS
  (no MoltenVK translation overhead).
- MPS provides access to highly-optimized pre-built kernels (matrix
  multiply, ray tracing, image processing) without writing custom shaders.
- No Rust GPU crates — consistent with ADR-0010's 5-crate policy.

### Negative
- macOS-only (Metal framework not available on Linux/Windows).
- The Objective-C shims require macOS to build (xcrun + Metal framework).
- MPS requires macOS 10.13+ (Sierra) for basic MPS, macOS 11+ (Big Sur)
  for MPSRayIntersector.

### Neutral
- The Metal + MPS host layers are "Wrap" decisions per ADR-0022 — the
  Metal and MPS frameworks are OS-provided and wrapped by thin shims.

## Alternatives Considered

### Alternative A: Use MoltenVK on macOS (Vulkan → Metal translation)
Partially accepted — MoltenVK is available as a fallback via ADR-0026's
gpu_vulkan.c. However, native Metal avoids the translation overhead and
is preferred on macOS.

### Alternative B: Use wgpu (Rust GPU crate, which wraps Metal on macOS)
Rejected — violates ADR-0010's 5-crate policy and ADR-0022's "no Rust
GPU crates" requirement.

### Alternative C: No Metal support (Vulkan-only via MoltenVK on macOS)
Rejected — native Metal is preferred per ADR-0022 §cross-platform-GPU.
MoltenVK adds translation overhead and may not support all Metal features.
