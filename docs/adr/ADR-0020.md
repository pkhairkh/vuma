# ADR-0020: Fix broken `womb/net/*.vuma` imports (V-WOMB-1)

- **Status**: Accepted
- **Date**: 2026-08-01
- **Decision Maker**: VUMA compiler team
- **Supersedes**: (none)
- **Superseded by**: (none)

## Context

The Wave J audit (`docs/research/J-1-womb-layer.md`) discovered that
8 files in `womb/net/` carry `import` statements pointing to
non-existent paths. The `crypto/` subtree was reorganized into
subdirectories (`crypto/mac_kdf/`, `crypto/aead/`, `crypto/encoding/`,
etc.) but the imports in `womb/net/` were never updated.

The VUMA module resolver (`src/parser/src/resolver.rs:500-510`) is a
simple `base_dir.join(path)` with no fallback — if the import path
doesn't resolve to an existing file, compilation fails.

### Affected files

| File | Broken import | Should be |
|------|---------------|-----------|
| `womb/net/ssh.vuma` | `import "crypto/hmac.vuma"` | `import "crypto/mac_kdf/hmac.vuma"` |
| `womb/net/quic.vuma` | `import "crypto/hmac.vuma"` | `import "crypto/mac_kdf/hmac.vuma"` |
| `womb/net/tls12.vuma` | `import "crypto/hmac.vuma"` | `import "crypto/mac_kdf/hmac.vuma"` |
| `womb/net/tls13.vuma` | `import "crypto/hmac.vuma"` | `import "crypto/mac_kdf/hmac.vuma"` |
| `womb/net/http2.vuma` | `import "crypto/hmac.vuma"` | `import "crypto/mac_kdf/hmac.vuma"` |
| `womb/net/http3_mqtt_coap.vuma` | `import "crypto/hmac.vuma"` | `import "crypto/mac_kdf/hmac.vuma"` |
| `womb/net/websocket.vuma` | `import "crypto/hmac.vuma"` | `import "crypto/mac_kdf/hmac.vuma"` |
| `womb/lib/sys/email.vuma` | `import "crypto/hmac.vuma"` | `import "crypto/mac_kdf/hmac.vuma"` |

(Exact paths to be verified during implementation — the audit found
these 8 files; there may be more with different broken imports.)

### Impact

These 8 files are effectively **DEAD code today** — they cannot be
compiled by the VUMA toolchain because the imports fail to resolve.
The per-file compile harness in the test suite masks this by not
exercising these files.

This means:
- `womb/net/ssh.vuma`, `womb/net/quic.vuma`, `womb/net/tls12.vuma`,
  `womb/net/tls13.vuma`, `womb/net/http2.vuma`,
  `womb/net/http3_mqtt_coap.vuma`, `womb/net/websocket.vuma` are
  non-functional.
- `womb/lib/sys/email.vuma` is non-functional.
- The SWE package's proposal to use `womb/net/websocket.vuma` for the
  UI engine's network layer is blocked until this is fixed.

## Decision

**Fix the broken imports. Update all 8 files to point to the correct
`crypto/mac_kdf/hmac.vuma` path (or whatever the correct path is after
verifying the current `womb/crypto/` structure).**

### Implementation

1. **Audit all imports in `womb/net/` and `womb/lib/`** — grep for
   `import "crypto/` to find every file that references the old
   `crypto/` flat layout.
2. **Map each broken import to the correct new path.** The
   `womb/crypto/` subtree was reorganized into:
   - `womb/crypto/mac_kdf/` — HMAC, KDF
   - `womb/crypto/aead/` — authenticated encryption
   - `womb/crypto/encoding/` — base64, hex, etc.
   - `womb/crypto/hash/` — SHA-256, BLAKE3, etc.
   - (Verify the exact structure during implementation.)
3. **Update each broken import.** Mechanical sed pass.
4. **Add a CI check** that compiles every `.vuma` file in `womb/` to
   catch future import breakage. (This is also V-NEW-8 from the
   catalog — the full test matrix should be in CI.)
5. **Add a regression test** that imports `womb/net/websocket.vuma`
   and compiles it, to prevent future breakage.

## Consequences

### Positive
- **8 dead files become live again.** `womb/net/websocket.vuma` is
  needed for the WOMB UI engine's network layer (per the SWE package).
- **CI catches future breakage.** The new CI check (compile every
  `.vuma` file) prevents silent import rot.
- **Mechanical fix.** No design decisions, just path updates.

### Negative
- **None.** This is a pure bugfix.

### Neutral
- The `womb/crypto/` reorganization that caused this was the right
  call (the flat layout didn't scale), but the import updates were
  forgotten. This ADR closes that gap.

## Alternatives Considered

### Alternative A: Leave the 8 files dead; document them as non-functional
Rejected — the SWE package's UI engine needs `womb/net/websocket.vuma`.
Leaving it dead blocks the UI work.

### Alternative B: Roll back the `womb/crypto/` reorganization
Rejected — the reorganization was correct (the flat layout didn't
scale). Fixing the imports is the right fix.

### Alternative C: Add a fuzzy resolver that searches for the import
Rejected — fuzzy resolution makes imports unpredictable. Explicit
paths are better.
